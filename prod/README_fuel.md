# Запуск модели со своей картой топлива

## 1. Что скачать (сервер, `/data/Beibars/fire-spread/`)
- `FireSpread_model_weights.zip` — код движка (`prod/`, `task2_model/scripts/`) и веса.
- `FireSpread_data_1_static.zip` — статические слои 500 м (рельеф, OSM, NDVI, топливо `lc.npz`).
- `FireSpread_data_2_years.zip` — погодичные слои (гари, NDVI).
- `FireSpread_fuel_update.zip` — этот README, `prod/fuel_import.py` и обновлённый `prod/landscape.py`.

Распакуйте всё в одну папку (пути внутри архивов уже правильные). `fuel_update` распаковывайте последним, с заменой файлов.

Нужен Python 3.10+ с `numpy pandas torch rasterio pyproj scipy`.

## 2. Перевести свою карту на сетку модели
Карта должна быть GeoTIFF в EPSG:4326 с кодами FBFM40 (uint8, nodata 255). Охват может быть любым: регион или вся страна.
```
python prod/fuel_import.py --tif fueltype_labeled_kz_k40.tif \
    --base task1_dataset/data/ext_kz/lc.npz --meta task1_dataset/data/ext_kz/slices_v3_channels.json \
    --out lc_custom.npz
```
Вся страна при 20 м обрабатывается за несколько минут, нужно около 4 ГБ памяти.

## 3. Запустить модель с новой картой
Новая карта включается переменной окружения `FIRE_LC`. Без неё модель берёт базовую `lc.npz` (WorldCover + старая FBFM40).
Команды запускаются из корня распакованной папки:
```
python -X utf8 -m prod.example_fuel 80.3 50.3                         # базовое топливо
FIRE_LC=lc_custom.npz python -X utf8 -m prod.example_fuel 80.3 50.3   # своё топливо
FIRE_LC=lc_custom.npz python -X utf8 -m prod.checks                   # проверки: рост по ветру, негорючее не горит (~30 мин)
```
- В Windows PowerShell переменную задают так: `$env:FIRE_LC="lc_custom.npz"`.
- Аргументы `example_fuel`: `lon lat [скорость ветра, м/с] [откуда дует, град]`.
- Погода в примере задаётся вручную: T = 30 °C, RH = 20 %. Боевой прогноз берёт погоду GFS по сети: `FireEngine().predict(lon=..., lat=..., t_utc=...)`.

## Как карта попадает в модель
- Коды FBFM40 сводятся в 5 групп топлива, по ним берутся доли в каждой ячейке 500 м:
  | группа | коды FBFM40 |
  |---|---|
  | трава | GR, GS |
  | пашня | 93 |
  | кусты и лес | SH, TU, TL |
  | болото | всегда 0 |
  | негорючее | 91, 92, 98, 99 |
- Через эти доли считается скорость распространения в физике (`sim_physics.fuel_factor`: трава 1, пашня 0,6, кусты и лес 0,4, болото 0,2, негорючее 0). Те же доли подаются каналами в U-Net.
- Канал `fbfm40` U-Net обучался на старой карте, где были только коды 99, 101, 102, 104 и 121. Поэтому новые коды сводятся к ним:
  - GR1 → 101;
  - GR2, GR3 → 102;
  - GR4–9 → 104;
  - GS, SH, TU, TL → 121;
  - NB → 99.

  Полный код FBFM40 сохраняется в `fbfm40_full`.
- Ячейки, которые карта покрывает меньше чем на 50 %, остаются из базового `lc.npz`.
- Модель не переобучалась под новую карту. Если вы меняете топливо, меняется физика, а U-Net видит только доли групп.

Пример готового файла: `lc_vko_abai.npz`, сделан из карты ВКО и Абая (`fueltype_labeled_vko_abai_k40.tif`).

## Один пожар: `prod/simulate_fire.py`
Скрипт моделирует распространение огня от точки возгорания. Карта топлива может покрывать только район пожара.
```
python -X utf8 -m prod.simulate_fire --lon 80.3 --lat 50.3 --t "2024-08-10 06:00" --hours 72 --fuel_tif my_fuel.tif --compare --out fire1
```
- Время `--t` задаётся в UTC. Погода берётся реальная из open-meteo (ERA5 или GFS), для этого нужен интернет. Погоду можно задать вручную: `--wind 8 270 --T 30 --RH 20`.
- Карта из `--fuel_tif` переводится на сетку модели один раз и сохраняется рядом как `<tif>.lc500.npz`.
- `--compare` делает второй прогон на базовом топливе.
- На выходе:
  - `fire1_custom.geojson` — контуры гари каждые 12 ч;
  - `fire1_custom.png` — карта времени прихода огня;
  - таблица площадей в консоли.
